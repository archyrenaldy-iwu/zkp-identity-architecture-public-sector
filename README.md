# SIPSI AI x Blockchain: Zero-Knowledge Identity Verification Architecture for Public-Sector Platforms

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.XXXXXXX.svg)](https://doi.org/10.5281/zenodo.XXXXXXX)

## 1. Title and Description

Official codebase, smart contracts, zero-knowledge circuits, AI microservices, datasets, and mainnet verification scripts for the paper:

> **Bytecode Security Auditing and Live Mainnet Validation of a Zero-Knowledge Identity Verification Architecture for Public-Sector Blockchain Platforms** (PeerJ Computer Science, manuscript CS-2026:08:147906)

The paper describes a 3+1 Parameter Augmentation scheme (Groth16 over BN254, Poseidon commitments, Sparse Merkle Tree), deterministic nullifier anti-replay state-locking, Mythril bytecode auditing, and live Polygon Mainnet validation (Chi-Square session unlinkability test). Implementation and reproduction caveats found in this repository snapshot are called out below.

## 3. Dataset Information

| File | Content | Used for |
|---|---|---|
| `data/polygon_mainnet_transactions_zkp.csv` | Raw Polygon Mainnet logs of the ZKP identity contract (`0xF99024c6E16c2dCCA305DAF4406b17D93F22a72f`); paper reports n = 229, but this CSV currently contains 122 data rows | Chi-Square unlinkability test (Equation 4 in the paper); reconcile sample size before claiming reproduction |
| `data/polygon_mainnet_transactions_sengketa.csv` | Raw Polygon Mainnet logs of the dispute workflow contract (`0x7f6979426Bf7eBcA11C81025359D123b8B9C5Baf`) | Gas cost and method distribution (Figures 6-7) |
| `data/ai_rekomendasi_retrain.csv` | Labeled data, RoBERTa 13-class legal recommendation | Module 4 |
| `data/ai_verifikasi_retrain.csv` | Labeled data, IndoBERT NER | Module 3 |

**Provenance (third-party data):** administrative dispute records come from the JDIH (Jaringan Dokumentasi dan Informasi Hukum) of the Central Information Commission of the Republic of Indonesia (Komisi Informasi Pusat RI), public documents under Law No. 14 of 2008 (KIP Act). Mainnet logs were generated by the authors' own contracts and are verifiable on Polygonscan.

**Privacy statement (audit incomplete):** the project documentation states that citizen identities are represented by Poseidon hash commitments and raw NIK/credential witnesses stay off-chain. A basic search found no standalone 16-digit sequences in the four CSV files, but a full manual privacy/provenance review has not been completed; this is not a certification that the repository contains no personal data.

## 4. Code Information

| Component | File | Result reported in the paper |
|---|---|---|
| ZKP circuit | [IdentityMerkleProof.circom](zkp-identity-proof/circuits/IdentityMerkleProof.circom) | Paper-reported: 8,372 non-linear constraints, 9,545 linear constraints, 2.14 s proving; not independently rerun for this README update |

| Verifier | [IdentityMerkleVerifier.sol](zkp-identity-proof/contracts/IdentityMerkleVerifier.sol) | Paper-reported Mythril result: 0 high/medium findings (SWC-113 low, informational); not independently rerun for this README update |

**Important consistency note:** the checked-in `IdentityMerkleZKP` contract explicitly allows repeated verification, and the existing test suite includes a test expecting two verifications to succeed (that proof-dependent test is skipped when generated proof files are absent). Therefore the paper's 50/50 anti-replay result is **not reproducible from the currently checked-in contract and tests**. Reconcile the paper's tested contract/version with this repository before presenting the replay result as verified or publishing an archival release.

## 6. Usage Instructions

```bash
git clone https://github.com/archyrenaldy-iwu/zkp-identity-architecture-public-sector.git
cd zkp-identity-architecture-public-sector

# Module 1 and 2
cd zkp-identity-proof && npm ci && cd ..
cd sengketa-contract && npm ci && cd ..

# Modules 3 and 4
cd ai-service && pip install -r requirements.txt && cd ..
```

Run the available tools from a fresh clone (commands below assume the repository root as the starting directory):

```bash
# 1. Circuit compilation (Figure 3)
cd zkp-identity-proof
circom circuits/IdentityMerkleProof.circom --r1cs --wasm --sym -l node_modules

# 2. Existing contract unit tests; these do not reproduce 50 blocked replay attempts
npm test

# 3. Bytecode audit (Figure 4)
cd ..
docker run --rm -v "$(pwd):/repo" mythril/myth:0.24.8 analyze \
  /repo/zkp-identity-proof/contracts/IdentityMerkleVerifier.sol \
  /repo/zkp-identity-proof/contracts/IdentityMerkleZKP.sol \
  /repo/zkp-identity-proof/contracts/IdentityVerifier.sol \
  /repo/zkp-identity-proof/contracts/IdentityZKP.sol \
  --solv 0.8.20 --execution-timeout 600

# 4. AI service
cd ai-service && python app.py
```

The paper reports a Chi-Square result (chi2 = 1.24, p = 0.265) from `data/polygon_mainnet_transactions_zkp.csv`, observed frequencies against a uniform expectation, alpha = 0.05. The repository snapshot does not currently document a script/command that reproduces this calculation, and the CSV currently has 122 data rows rather than the paper-reported n = 229; treat the statistic as paper-reported until the sample discrepancy is resolved and the analysis is supplied and rerun.

## 7. Methodology

The work follows the six-stage Design Science Research Methodology (Peffers et al., 2007): (1) problem identification, (2) solution objectives (< 10,000 gates, bytecode audit, alpha = 0.05 test), (3) design and development, (4) demonstration on Polygon Mainnet, (5) evaluation (Circom audit, Mythril, Hardhat, Chi-Square), (6) communication. The mainnet sample was undersampled from imbalanced logs (rejected records about 1.38%) to n = 229.
