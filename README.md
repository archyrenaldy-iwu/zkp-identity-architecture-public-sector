# SIPSI AI x Blockchain: Zero-Knowledge Identity Verification Architecture for Public-Sector Platforms

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23334713.svg)](https://doi.org/10.5281/zenodo.23334713)

## 1. Title and Description

Official codebase, smart contracts, zero-knowledge circuits, AI microservices, datasets, and mainnet verification scripts for the paper:

> **Bytecode Security Auditing and Live Mainnet Validation of a Zero-Knowledge Identity Verification Architecture for Public-Sector Blockchain Platforms** (PeerJ Computer Science, manuscript CS-2026:08:147906)

The project combines a 3+1 Parameter Augmentation scheme (Groth16 over BN254, Poseidon commitments, Sparse Merkle Tree), deterministic nullifier anti-replay state-locking, Mythril bytecode auditing, and live Polygon Mainnet validation (Chi-Square consistency check).

## 3. Dataset Information

| File | Content | Used for |
|---|---|---|
| `data/polygon_mainnet_transactions_zkp.csv` | Raw Polygon Mainnet logs of the baseline contract (122 rows) | Chi-Square test (Equation 4); `scripts/calculate_chi_square.py` |
| `data/polygon_mainnet_transactions_sengketa.csv` | Raw Polygon Mainnet logs of the hybrid contract (107 rows; 122 + 107 = 229 transactions) | Gas cost and method distribution (Figures 6-7) |
| `data/ai_rekomendasi_retrain.csv` | Labeled data, RoBERTa 13-class legal recommendation (1,021 rows, 1,020 unique samples) | Module 4 |
| `data/ai_rekomendasi_retrain_en.csv` | English-annotated copy with statutory category mappings (UU No. 14/2008) | Data transparency & peer review |
| `data/ai_verifikasi_retrain.csv` | Reference dispute text dataset (see note below) | Module 3 |
| `data/CODEBOOK_EN.md` | Comprehensive English Codebook explaining data schema, categories, and legal basis | Peer review & reproduction |

**Data Dictionary & English Codebook:** An extensive English codebook is available at [`data/CODEBOOK_EN.md`](data/CODEBOOK_EN.md) along with the English-annotated dataset [`data/ai_rekomendasi_retrain_en.csv`](data/ai_rekomendasi_retrain_en.csv). Raw text entries remain in Indonesian to preserve the statutory syntax and domain-specific acronyms of public administrative dispute jurisprudence under UU No. 14 of 2008.

**Provenance (third-party data):** administrative dispute records come from the JDIH (Jaringan Dokumentasi dan Informasi Hukum) of the Central Information Commission of the Republic of Indonesia (Komisi Informasi Pusat RI), public documents under Law No. 14 of 2008 (KIP Act). Mainnet logs were generated by the authors' own contracts and are verifiable on Polygonscan.

**Privacy:** citizen identities are represented only by Poseidon hash commitments. Raw NIK and credential witnesses stay off-chain and are not in this repository.

## 6. Usage Instructions

```bash
git clone https://github.com/archyrenaldy-iwu/zkp-identity-architecture-public-sector.git
cd zkp-identity-architecture-public-sector

# Module 1 and 2
cd zkp-identity-proof && npm install && cd ..
cd sengketa-contract && npm install && cd ..

# Modules 3 and 4
cd ai-service && pip install -r requirements.txt && cd ..
```

Reproduce the paper results:

```bash
# 1. Circuit compilation (Figure 3)
cd zkp-identity-proof
circom IdentityMerkleProof.circom --r1cs --wasm --sym -l node_modules

# 2. Replay-attack simulation, 50 duplicate proofs (Figure 5; uses MockGroth16Verifier)
npx hardhat test test/ReplayAttackSimulation.js

# 3. Bytecode audit (Figure 4)
docker run -v ${PWD}:/tmp mythril/myth:0.24.8 analyze /tmp/IdentityMerkleVerifier.sol /tmp/IdentityMerkleZKP.sol /tmp/IdentityVerifier.sol /tmp/IdentityZKP.sol --execution-timeout 600

# 4. AI service
cd ../ai-service && python app.py
```

```bash
python scripts/calculate_chi_square.py   # n = 229, chi2 = 0.98, p = 0.322
```

The test compares transaction counts of the two contracts (122 vs 107) against an equal split, alpha = 0.05. All transactions come from one author-controlled account, so it is a preliminary consistency check, not a test of inter-user linkability. Of the 229 transactions, 42 are proof transactions (24 Submit Proof, 18 Verify Identity).

## 7. Methodology

The work follows the six-stage Design Science Research Methodology (Peffers et al., 2007): (1) problem identification, (2) solution objectives (< 10,000 gates, bytecode audit, alpha = 0.05 test), (3) design and development, (4) demonstration on Polygon Mainnet, (5) evaluation (Circom audit, Mythril, Hardhat, Chi-Square), (6) communication. The mainnet dataset consists of all 229 transactions of the two deployed contracts.
